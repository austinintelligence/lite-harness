# Delegated runtimes

Lite-Harness supports owner-local delegated execution through official Codex
and Claude processes. It never extracts a subscription credential or reuses it
as an API token. The delegated process owns its inner loop; Manager still owns
the outer run, timeout, durable usage/events, cancellation, workspace queue,
and agent tool policy.

## Codex app-server

Set `LITE_HARNESS_PROVIDER=codex`. The adapter launches `codex app-server` on
stdio, performs `initialize` / `initialized`, starts an ephemeral thread and
turn, normalizes agent-message and token-usage notifications, and interrupts
the active turn on cancellation. `CODEX_HOME` may point at an isolated profile.
Approval requests fail closed unless a Manager approval broker explicitly
accepts them.

The protocol implementation follows the current official
[Codex app-server documentation](https://developers.openai.com/codex/app-server)
and version-matched schemas generated by the installed Codex CLI.

## Claude Code

Set `LITE_HARNESS_PROVIDER=claude`. The adapter launches the official CLI in
non-interactive `stream-json` mode. `LITE_HARNESS_DELEGATED_TOOLS` is empty by
default; explicitly list approved built-in Claude tools to enable inner-loop
actions. `LITE_HARNESS_DELEGATED_MAX_BUDGET_USD` adds the CLI-native cost cap.

Both adapters use direct process spawning without a shell, bounded JSONL lines,
bounded diagnostics, a minimal inherited environment, deadlines, abort
propagation, and forceful cleanup after the graceful deadline. For multi-user
or remotely exposed applications, use documented provider API credentials
unless the provider expressly authorizes delegated subscription automation.
